# Outputs and report layout

Every run ends with the same **six outputs plus an update check**. All six are generated by
`scripts/build_outputs.py` from one canonical file, `findings.json` (fields: `findings-schema.md`),
so they can never disagree. Do not hand-write the brief or report; fill `findings.json` and
run the builder. Redact secrets and personal data to the last four characters before writing
`findings.json`.

```bash
python3 scripts/build_outputs.py --findings .appaudit/findings.json \
  --scope .appaudit/scope.json --evidence .appaudit/evidence/evidence.jsonl \
  --out .appaudit/reports [--update-source <url-or-path>] [--plugin-root <dir>]
```

The builder writes a new folder `<out>/<YYYY-MM-DD>-<engagement>/` on every run (it never
overwrites an earlier run) and refuses to build when `findings.json` has errors.

| # | File | Audience | Contents |
|---|------|----------|----------|
| 1 | `brief.md` | Board, management, counsel | One page: deadlines that may be running, posture, top risks, decisions needed, readiness items, coverage, integrity and version |
| 2 | `report.md` | Engineers, assessor's file | Full technical report (layout below), regulatory trigger register, disclosure routing, build checks |
| 3 | `findings.json` | Pipelines, archive | Canonical data, normalized and sorted |
| 4 | `findings.sarif` | CI / GitHub code scanning / IDE | SARIF 2.1.0; code-located findings only (others are counted in the run properties) |
| 5 | `findings-register.xlsx` | Remediation owners | Sheet "Findings" (owner, due date, status, re-test) and sheet "Regulatory" (finding × jurisdiction) |
| 6 | `evidence-bundle.zip` | Auditors | `findings.json`, `scope.json`, `evidence.jsonl`, `evidence-verification.json`, `update-check.json`, inner `MANIFEST.sha256` |
| + | `update-check.json` | Maintainer | Installed vs. published version; age of standards and regulatory data. Reports only; never downloads or installs |
| + | `MANIFEST.sha256` | Anyone | SHA-256 of every deliverable, including the bundle |

On request only: OSCAL Assessment Results + POA&M (v1.2.x), CycloneDX VDR/VEX, CSAF 2.0.

## Brief layout (`brief.md`, one page)

1. **Deadlines that may be running** — every `may_trigger_now` flag: finding, jurisdiction,
   instrument, deadline, when the clock starts, authority. "For client/counsel decision."
2. **Overall posture** — posture, counts by severity × confidence, SSVC counts.
3. **Top risks** — at most five, ordered by SSVC decision, then CVSS-BTE score.
4. **Decisions needed** — from `summary.decisions_needed`, every `may_trigger_now` flag and
   every disclosure conflict.
5. **Prepare for** — `readiness` flags grouped by instrument.
6. **Coverage** — jurisdictions assessed / not assessed, not tested, calls blocked by the scope guard.
7. **Integrity and version** — evidence-chain result, update-check result, pointer to
   `MANIFEST.sha256`.

## Technical report layout (`report.md`)

```markdown
# Security Assessment — <engagement name>

**Date:** <date>  **Assessor:** <assessor>  **Tool:** appaudit <version> (standards checked <date>, regulatory data checked <date>)

## 1. Executive summary
- Overall posture · permission to test (declared by the assessor, not verified by appaudit) · mode · tested scope · out of scope / not tested
- Runtime capabilities used · threat-intel refresh date
- Jurisdictions assessed / not assessed · regulatory flags (may trigger now / readiness)
- Totals by severity and confidence; SSVC counts

## 2. Findings (ordered by SSVC decision, then CVSS-BTE score)
### [<SEVERITY>] <ID> <Title>
- Identifiers: CWE · OWASP · ASVS · OpenCRE · CVE
- Severity: CVSS-BTE <score> `<vector>` · [verify](<calculator_url>)
- Priority: SSVC <decision> (Exploitation / Automatable / Technical Impact / Mission & Well-being) · EPSS · KEV
- Confidence: <assessor> · verifier verdict: <verdict> (<notes>)
- Asset · location · status · owner
- Proof (benign) · root cause · impact
- Remediation (copy-paste patch) · regression note
- Remediation timeline: <basis> — due <date>
- Re-test: action / expected result
- Regulatory flags (tier, instrument, deadline) · disclosure routing
- Evidence: log records <seq…>

## 3. Informational / hardening
## 4. Verified not applicable
## 5. Re-test plan (table)
## 6. Regulatory trigger register (finding × jurisdiction, both tiers, with basis and source date)
## 7. Disclosure routing and conflicts
## 8. Evidence & data handling (raw evidence location, access, chain verification, secrets found and rotation advice)
## Appendix — build checks and deliverable manifest
```
